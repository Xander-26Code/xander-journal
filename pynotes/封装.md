# 封装

封装是面向对象里非常核心的概念。你现在可以先把它理解成一句话：

**封装 = 把数据和操作这些数据的方法放到一个类里面，并尽量不让外部随便乱改内部数据。**

比如你有一个银行账户：

```Python
class BankAccount:
    def __init__(self, money):
        self.money = money

    def deposit(self, amount):
        self.money += amount

    def withdraw(self, amount):
        self.money -= amount
```

这里：

```Python
self.money
```

是账户的数据。

而：

```Python
deposit()
withdraw()
```

是操作这些数据的方法。

它们都被放在：

```Python
BankAccount
```

这个类里面。

这就是最基础的封装思想。

---

假设不使用类，我们可能这样写：

```Python
money = 1000

money += 500
money -= 200
```

问题是，谁都可以随便改：

```Python
money = -999999
```

程序完全拦不住。

但如果我们把钱封装进 `BankAccount`：

```Python
class BankAccount:
    def __init__(self, money):
        self.money = money

    def withdraw(self, amount):
        if amount > self.money:
            print("余额不足")
        else:
            self.money -= amount
```

使用：

```Python
account = BankAccount(1000)

account.withdraw(200)
```

这时候我们把“钱怎么减少”这件事情统一放进：

```Python
withdraw()
```

里面。

于是我们就可以规定：

```Plain Text
取钱之前先检查余额
```

而不是让外部程序到处乱写：

```Python
account.money -= 100000
```

这就是封装的意义之一：

**控制数据应该怎么被修改。**

---

你也可以把封装想象成一台汽车。

你开车的时候会操作：

```Plain Text
方向盘
油门
刹车
档位
```

但是你通常不需要知道：

```Plain Text
发动机里面每个活塞怎么运动
变速箱内部齿轮怎么啮合
喷油系统怎么喷油
```

汽车把内部复杂结构“封装”起来，只给你几个简单接口：

```Plain Text
踩油门
踩刹车
转方向盘
```

编程也是一样。

例如：

```Python
account.withdraw(100)
```

你只需要知道：

> `withdraw()` 可以取钱。
> 
> 

至于它内部：

```Python
def withdraw(self, amount):
    if amount <= 0:
        return

    if amount > self.money:
        print("余额不足")
        return

    self.money -= amount
```

到底怎么实现，你在使用这个类的时候不一定需要关心。

所以封装还有第二层含义：

**隐藏内部实现，只暴露给外部需要使用的功能。**

---

### Python 里面怎么实现封装？

Python 的封装不像 Java 那么严格。

最普通的属性：

```Python
class Student:
    def __init__(self, name):
        self.name = name
```

外面可以直接：

```Python
student = Student("Tom")

print(student.name)

student.name = "Jerry"
```

所以：

```Python
self.name
```

实际上是公开的。

如果程序员希望表达：

> “这个属性主要给类内部使用，外面最好不要碰。”
> 
> 

通常可以加一个下划线：

```Python
class Student:
    def __init__(self, name):
        self._name = name
```

比如：

```Python
self._name
```

这叫一种命名约定。

它的意思不是“绝对不能访问”，而是告诉其他程序员：

> 这是内部属性，尽量不要直接操作。
> 
> 

实际上：

```Python
student._name
```

依然可以访问。

---

如果写两个下划线：

```Python
class BankAccount:
    def __init__(self, money):
        self.__money = money
```

那么：

```Python
account = BankAccount(1000)

print(account.__money)
```

通常会报错：

```Plain Text
AttributeError
```

因为 Python 会对：

```Python
__money
```

进行一种叫做 **name mangling（名称改写）** 的处理。

这时候我们通常通过方法访问：

```Python
class BankAccount:
    def __init__(self, money):
        self.__money = money

    def get_money(self):
        return self.__money
```

然后：

```Python
account = BankAccount(1000)

print(account.get_money())
```

输出：

```Plain Text
1000
```

这样外部就不是直接操作：

```Python
__money
```

而是通过我们规定好的接口操作。

---

例如进一步设计：

```Python
class BankAccount:
    def __init__(self, money):
        self.__money = money

    def deposit(self, amount):
        if amount > 0:
            self.__money += amount

    def withdraw(self, amount):
        if amount <= self.__money:
            self.__money -= amount
        else:
            print("余额不足")

    def get_money(self):
        return self.__money
```

使用：

```Python
account = BankAccount(1000)

account.deposit(500)
account.withdraw(300)

print(account.get_money())
```

结果：

```Plain Text
1200
```

这里的设计就是：

```Plain Text
__money
    ↓
内部数据，不希望别人乱改

deposit()
withdraw()
get_money()
    ↓
提供给外界使用的接口
```

这就是一个比较典型的封装。

---

### 为什么封装很重要？

假设我们完全不封装：

```Python
player.hp = -100000
player.level = -5
player.money = "哈哈哈哈"
```

外部想怎么改就怎么改，很容易让对象进入一个不合理的状态。

如果封装起来：

```Python
class Player:
    def __init__(self):
        self.__hp = 100

    def take_damage(self, damage):
        self.__hp -= damage

        if self.__hp < 0:
            self.__hp = 0
```

外面通过：

```Python
player.take_damage(50)
```

修改生命值。

那么类自己就可以保证：

```Plain Text
HP 最低只能是 0
```

这样程序会更加安全、稳定。

---

你还可以把之前学的知识串起来。

比如：

```Python
class Player:
    def __init__(self, name):
        self.name = name
        self.__hp = 100

    def take_damage(self, damage):
        self.__hp -= damage

    def get_hp(self):
        return self.__hp
```

这里：

```Python
__init__()
```

负责初始化对象：

```Plain Text
name
hp
```

而封装负责：

```Plain Text
__hp 不让外部直接随便操作
```

然后：

```Python
take_damage()
get_hp()
```

作为外部使用这个对象的方式。

可以画成：

```Plain Text
Player
        ┌───────────────┐
        │               │
        │ name           │
        │ __hp           │ ← 内部数据
        │               │
        │ take_damage() │
        │ get_hp()      │ ← 对外接口
        │               │
        └───────────────┘
                ↑
                │
             外部程序
```

外部程序最好通过：

```Python
player.take_damage(20)
```

而不是：

```Python
player.__hp = ???
```

---

### 不过有一个很重要的误区

**封装不等于“给所有变量都加 ****`__`****”。**

很多初学者会觉得：

> 面向对象要求封装，所以所有属性全部写 `self.__xxx`。
> 
> 

其实不是。

Python 的风格本身比较开放。

例如很正常的类：

```Python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age
```

完全没有问题。

只有当你真的有：

```Plain Text
不希望外界直接操作的数据
内部实现细节
需要控制修改规则的数据
```

才有必要考虑 `_xxx`、`__xxx`、`property` 等方式。

所以你现阶段不要机械地认为：

```Plain Text
封装 = private变量
```

更重要的思想是：

> **对象自己管理自己的数据，对外提供清晰的使用方式。**
> 
> 

---

你现在可以把面向对象学到的几个知识串起来：

```Plain Text
类 class
    ↓
对象的模板

对象 object
    ↓
根据类创建出来的具体实例

__init__
    ↓
初始化对象的数据

self
    ↓
当前这个对象

属性
    ↓
对象有什么数据

方法
    ↓
对象能做什么

封装
    ↓
把数据和操作数据的方法组织在一起，
控制外部如何访问和修改内部状态
```

最推荐你记住的定义是：

**封装就是把对象的数据和相关操作包装在类中，并通过合适的方法控制外界如何访问和修改这些数据，从而隐藏不必要的内部实现细节。**
