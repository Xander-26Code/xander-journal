# Python 的 `if __name__ == "__main__"` 到底在判断什么？

刚开始学习 Python 时，经常会在代码末尾看到这两行：

```python
if __name__ == "__main__":
    main()
```

照着写，程序能运行；把它删掉，程序似乎也能运行。那为什么还要加它？

这个问题的答案，藏在同一个 Python 文件的两种使用方式里：**它既可以作为程序入口运行，也可以被其他文件导入，提供函数、类和常量。** 入口判断让这两种用途能够共存。

下面从一个“导入时意外打印”的例子出发，理解这行代码，并把它用到命令行程序和 Python 包中。文中的示例只依赖标准库。

## 1. 为什么只是导入一个函数，也会执行打印？

新建两个文件，放在同一个目录下：

```text
project/
├── calculator.py
└── app.py
```

`calculator.py` 提供一个加法函数，顺手写两行代码试一下：

```python
# calculator.py

def add(a, b):
    return a + b


print("正在测试加法函数")
print(add(2, 3))
```

`app.py` 想复用这个函数：

```python
# app.py
from calculator import add

print("业务计算结果：", add(10, 20))
```

在这个目录下执行：

```bash
python app.py
```

输出却包含三行：

```text
正在测试加法函数
5
业务计算结果： 30
```

原因是：**导入 Python 源码模块时，解释器需要执行它的顶层代码，建立模块中的名字。** `def` 语句会建立函数，顶层的 `print()` 则会直接执行。`from calculator import add` 也需要先加载模块，并不是只截取 `add` 的代码。

不过，在同一个解释器进程中，模块成功导入后通常会被缓存在 `sys.modules` 中。再次按同一个模块名导入，一般会复用已有模块，不会重新执行全部顶层代码。显式重新加载等情况另当别论。这个过程可以参阅 [Python 官方模块教程](https://docs.python.org/3/tutorial/modules.html)。

如果示例代码不是打印，而是 `input()`、启动服务或连接数据库，那么一次普通导入就可能产生意料之外的行为。

## 2. `__name__` 是什么？

`__name__` 是模块命名空间中的一个特殊变量，由 Python 设置。对本文讨论的普通 `.py` 模块，可以先看下面两种情况：

| 使用方式 | 例子 | 该模块中的 `__name__` |
| --- | --- | --- |
| 作为程序入口执行 | `python calculator.py` | `"__main__"` |
| 被其他模块导入 | `import calculator` | `"calculator"` |
| 作为包内模块被导入 | `import demo.calculator` | `"demo.calculator"` |

注意拼写：变量是 `__name__`，比较的字符串是 `"__main__"`，两侧都有两个下划线。`"main"` 和 `"__main__"` 是不同的字符串。

可以把 `calculator.py` 暂时改成下面这样观察：

```python
# calculator.py
print(f"当前模块的 __name__ = {__name__}")
```

直接运行 `python calculator.py`，输出：

```text
当前模块的 __name__ = __main__
```

在另一个新启动的 Python 进程里执行 `import calculator`，输出：

```text
当前模块的 __name__ = calculator
```

**`__name__` 描述的是模块这一次以什么身份执行，而不只是文件叫什么。** 入口身份还可以来自 `python -m` 等运行方式，后面会用到。完整规则见 [官方 `__main__` 文档](https://docs.python.org/3/library/__main__.html)。

## 3. 入口判断究竟保护了哪些代码？

恢复加法函数，并把试运行代码放进判断块：

```python
# calculator.py

def add(a, b):
    return a + b


if __name__ == "__main__":
    print("正在测试加法函数")
    print(add(2, 3))
```

现在，直接执行 `python calculator.py`，条件成立，仍然输出测试结果；执行前面的 `python app.py`，条件不成立，只输出：

```text
业务计算结果： 30
```

这里容易产生一个误解：“写了入口判断，导入时整个文件就不执行了。”

实际上，解释器依然会执行顶层代码，包括 `def` 和这个 `if` 语句，只是不会进入条件为假的分支。**只有缩进在入口判断下面的代码，才受这个条件控制。**

例如：

```python
# demo.py
print("A：顶层语句")


def greet():
    print("B：函数体")


if __name__ == "__main__":
    print("C：入口分支")
    greet()
```

直接运行时输出：

```text
A：顶层语句
C：入口分支
B：函数体
```

在新进程中首次 `import demo` 时，仅输出：

```text
A：顶层语句
```

导入之后仍然可以调用 `demo.greet()`，得到 `B：函数体`。函数一直可用，只是没有在导入过程中被自动调用。

这个例子也说明：函数体通常在调用时执行，但定义函数本身发生在导入阶段；默认参数表达式、装饰器等也可能在定义阶段求值或执行，不能把所有定义都当成完全没有副作用。

## 4. 为什么通常还要写一个 `main()`？

入口判断里可以直接放业务代码，但当程序变长后，更清楚的组织方式是：

```python
# greeting.py

def make_greeting(name):
    return f"你好，{name}！"


def main():
    name = input("请输入名字：").strip()
    print(make_greeting(name))


if __name__ == "__main__":
    main()
```

三个部分各有职责：

- `make_greeting()` 提供可以复用和测试的功能。
- `main()` 组织输入、调用和输出，描述程序的执行流程。
- 入口判断决定这次是否启动流程。

`main` 只是普通函数名，并不是 Python 关键字。你也可以叫它 `run()`，但 `main()` 更容易让读者认出入口。

还有一个实际区别：`if` 不会创建独立的局部作用域，而函数会。把流程放进 `main()`，其中的临时变量就不会变成模块级变量。

## 5. 一个可直接使用的命令行示例

下面把加法工具整理成既能导入、又能从命令行调用的形式。将代码保存为 `sum_cli.py`：

```python
import argparse


def add(a, b):
    return a + b


def main(argv=None):
    parser = argparse.ArgumentParser(description="计算两个整数的和")
    parser.add_argument("a", type=int, help="第一个整数")
    parser.add_argument("b", type=int, help="第二个整数")
    args = parser.parse_args(argv)

    print(add(args.a, args.b))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

运行：

```bash
python sum_cli.py 10 20
```

输出 `30`。运行 `python sum_cli.py --help`，还能看到参数说明。

这里的 `argv=None` 表示默认读取命令行参数；需要在代码中验证入口行为时，也可以传入列表，例如 `main(["10", "20"])`。参数解析行为见 [官方 `argparse` 文档](https://docs.python.org/3/library/argparse.html)。

`raise SystemExit(main())` 会先执行 `main()`，再将返回值作为退出状态交给解释器。返回 `0` 通常表示成功，非零整数通常表示失败。这与 `sys.exit(main())` 是常见的两种入口写法。不要为了“返回结果”而在这里返回任意字符串：传给 `SystemExit` 的字符串会作为错误信息输出，通常对应退出码 `1`。参见 [官方 `sys.exit()` 说明](https://docs.python.org/3/library/sys.html#sys.exit)。

与此同时，其他程序仍然可以安全地复用加法函数：

```python
from sum_cli import add

assert add(10, 20) == 30
```

导入不会触发参数解析，也不需要为测试准备命令行输入。

## 6. `python 文件.py` 和 `python -m 包.模块` 有什么区别？

假设项目结构是：

```text
project/
└── demo/
    ├── __init__.py
    ├── helpers.py
    └── app.py
```

`__init__.py` 留空，`helpers.py` 写入：

```python
# demo/helpers.py

def greet(name):
    return f"你好，{name}！"
```

`app.py` 写入：

```python
# demo/app.py
from .helpers import greet


def main():
    print(greet("Xander"))


if __name__ == "__main__":
    main()
```

在 `project` 目录下执行：

```bash
python -m demo.app
```

程序输出 `你好，Xander！`，且 `demo.app` 作为入口运行时，`__name__` 仍然是 `"__main__"`。

如果改成 `python demo/app.py`，这里的相对导入通常会失败，因为直接按文件路径执行时，没有建立相同的包上下文。`-m` 会通过模块搜索机制定位代码，并保留运行包内模块所需的上下文。参见 [官方命令行 `-m` 说明](https://docs.python.org/3/using/cmdline.html#cmdoption-m)。

如果希望进一步简化为 `python -m demo`，可以增加 `demo/__main__.py`：

```python
# demo/__main__.py
from .app import main

main()
```

这个文件专门承接包的执行入口，通常保持简短，把实际逻辑放在可导入的模块里。

要区分三个相似的名字：`__name__` 是变量，`"__main__"` 是特殊的模块名，`__main__.py` 是让包能够通过 `python -m 包名` 运行的入口文件。

## 7. 多进程代码为什么尤其需要入口保护？

采用 `spawn` 等启动方式时，子进程需要重新加载主模块。如果在模块顶层直接创建进程池，子进程加载模块时可能再次启动进程，导致启动错误。

因此，创建进程或进程池的启动逻辑应放在受入口判断保护的流程中，任务函数则通常定义在模块顶层，方便子进程定位。这个要求关系到程序能否正确启动，并不只是代码风格。具体限制见 [官方多进程安全导入说明](https://docs.python.org/3/library/multiprocessing.html#safe-importing-of-main-module)。

## 8. 用三个问题检查你的理解

**把文件重命名为 `main.py`，才会进入入口分支吗？**

不需要。文件名可以任意选择，判断的是运行身份。

**从其他文件导入后，还能调用 `main()` 吗？**

可以。入口判断控制自动调用；你仍然可以显式执行 `模块名.main()`。

**每个 Python 文件都必须写入口判断吗？**

不必须。只提供函数、类和常量的模块，可以没有独立启动流程，也就不需要为了形式而增加入口。

下次组织一个脚本时，可以先找出哪些代码是“别人也能复用的能力”，哪些是“这次运行才需要启动的流程”。把前者放在函数或类里，把后者交给 `main()` 和入口判断，文件就能同时承担脚本和模块的角色。
